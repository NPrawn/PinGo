# WebXR 지원 환경 및 pose 추적 검증 결과 (S15P11A206-294)

FR-U-010 상대 위치 추적의 구현 가능 범위와 fallback 기준을 실측으로 확정하기 위한 검증 기록이다.
결정 사항은 `기술_의사결정_정리.md` 11장, 좌표 정렬 제안은 `역삼역_FE_좌표연동_스펙.md` 8장에 있다.

> **이 문서의 원칙**: 실기기에서 직접 확인하지 않은 항목은 성공으로 적지 않는다. 확인 전에는 `미검증`으로 둔다.

## 2. 자동 검증 결과 (2026-07-29, 헤드리스 Chromium 149)

WebXR 기기가 없는 환경에서 확인 가능한 항목만 실행했다.

| 항목 | 결과 | 값 |
| --- | --- | --- |
| 페이지 로드·렌더 | 통과 | JS 오류 0건 |
| `http://127.0.0.1`의 `isSecureContext` | 통과 | `true` |
| `navigator.xr` 노출 | 통과 | 존재 |
| `isSessionSupported('immersive-ar')` | 통과(미지원 응답 정상 수신) | `false` |
| `isSessionSupported('inline')` | 통과 | `true` |
| 미지원 시 분기 | 통과 | 세션 시작 버튼 비활성화 + fallback 안내 로그 |

**여기서 확정된 것**: HTTPS 도메인 없이도 `localhost`/`127.0.0.1` 오리진은 secure context로 인정되어 `navigator.xr`이 노출된다. 운영 도메인·인증서가 미확정인 현재 상태에서도 실기기 검증을 진행할 수 있다는 뜻이다.

`immersive-ar`은 데스크톱 Chromium에서 원래 미지원이므로 위 `false`는 정상 결과이고, **지원 여부에 대한 판단 근거가 아니다.**

### 3.2 접속 방법

secure context가 필요하므로 다음 중 하나를 사용한다. LAN IP + http로는 `navigator.xr`이 노출되지 않는다.

```bash

cd frontend && npm run dev
adb reverse tcp:5173 tcp:5173
```

```bash
# 대안 — 무선. 폰 Chrome에서 chrome://flags#unsafely-treat-insecure-origin-as-secure에
#        http://<PC IP>:5173 등록 후 접속. 검증 후 플래그를 원복한다.
cd frontend && npm run dev:host
```

### 3.4 좌표 정렬 검증 방법 (16번)

`역삼역_FE_좌표연동_스펙.md` 8.3의 변환식은 **반사 없이 2D 회전만 적용한다는 계산상 추론**이며 실측 전이다. 검증 절차는 다음과 같다.

1. 세션을 시작해 첫 pose를 앵커로 잡는다.
2. 한 방향으로 직선 5m 걷고 페이지의 `Δx, Δz`를 기록한다.
3. 앵커로 돌아와 오른쪽으로 90° 돈 뒤 다시 5m 걷고 `Δx, Δz`를 기록한다.
4. 두 변위 벡터의 부호 조합이 8.3 식의 가정과 맞는지 확인한다. 다르면 `dZ` 항의 부호를 교정하고 그 결과를 8.3에 반영한다.

## 4. 현재 시점 결론

**확정된 것**

- `localhost` 터널링으로 HTTPS 도메인 없이 실기기 검증이 가능하다.
- 검증 페이지가 지원 탐지와 미지원 fallback 분기를 정상 수행한다.
- 미지원 시 동작은 위치 재인식 + 지도 수동 위치 선택이다(`기술_의사결정_정리.md` 11.7).

**확정하지 못한 것**

- 기준 Android 실기기에서 `immersive-ar` 세션과 pose 수집이 실제로 되는지 — 3장 전체가 미검증이다.
- 좌표 변환식의 축·부호.
- 앵커 시점 `mapYaw`의 출처. VPS 응답에 방향 필드가 없어 별도 합의가 필요하다(`기술_의사결정_정리.md` 12장).

따라서 **S15P11A206-295 이후 구현 범위는 3장 결과가 나온 뒤 확정한다.** 현재 문서에 적힌 필수 범위는 "WebXR을 사용한다"는 방향까지이며, 세부 구현 가능 범위는 이 문서 3장이 채워질 때 결정된다.
